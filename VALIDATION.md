# Проверка реализации

Проверено 21 октября 2026 года по местному времени. Реальный пилот Codex завершился **13/13** на двух локальных Git-проектах; независимая итоговая проверка прошла. Полная приёмка плана ещё не завершена: остаются реальные Claude/API, переключения двух аккаунтов и внешние PR/MR.

## Автоматические проверки

- Последний полный `.venv/bin/pytest -q` (21 октября 2026): **460 passed**. Ранее упавшие тесты делегирования и выбора исполнителей (`test_coordination.py`, `test_groups.py`, `test_quota.py`, `test_scheduler.py`) исправлены. Осталось предупреждение зависимости Starlette о будущем переходе тестового клиента с httpx на httpx2.
- `uv run ruff check darkfactory tests scripts`: все проверки прошли.
- `ruff format --check` для изменённых Python-файлов: формат корректен. Общая проверка: 54 файла соответствуют формату; существующие `tests/test_completion_notifications.py` и `tests/test_pipeline.py` требуют форматирования и оставлены без изменений.
- `node --check` для `app.js`, `registry.js`, `agents.js`, `chat.js`, `notifications.js`: синтаксис корректен.
- Docker Compose собран и запущен; приложение и PostgreSQL проходят healthcheck.

Тесты включают ограничения прав и токенов, зависимости и циклы, пулы и переключение исполнителей, восстановление и отмену, бюджеты дерева подзадач, инциденты preprod, привязку проверок и ревью к коммиту, повторную интеграцию и обработку дедлайнов Git. Адаптеры в этих тестах используют подставные ответы протоколов.

Отдельные регрессии проверяют смену принятого коммита зависимости: повтор реализации, проверок и ревью на настоящем локальном Git; остановку активного исполнителя и сохранение черновика; отклонение запоздалого ответа; запрет слияния при отзыве зависимости между heartbeat и Git. Цепочка артефактов не скрывает устаревший вход промежуточной задачи, даже если её собственный SHA ещё не изменился. Артефакт без коммита и независимого ревью не разблокирует очередь. Повтор приёмки сохраняет затраченное время, число исправлений и переключений. Миграция добавляет `tasks.dependency_commits` с пустым JSON и сохраняет существующие записи; повторный запуск миграции проверен тестом.

Полный конвейер на локальном Git проверен с обязательными проверками и без них: четыре документа проходят ревью, сохраняют SHA источника и появляются в реестре черновиками. Существующая принятая версия сохраняется; повторная публикация не создаёт лишних версий. Карта файлов доступна через API артефактов задачи. Изменение кода переводит задачу в цикл исправления; отсутствие, пустота, превышение лимита и символические ссылки отклоняются.

В браузере проверены создание проекта с включённой инициализацией, появление задачи и открытие той же задачи кнопкой «Индексировать проект». На ширине 1440 и 390 px просмотрены скриншоты, горизонтального переполнения страницы и ошибок JavaScript нет. Реальные платные вызовы и генерация документации моделью в этих проверках не запускались; исполнитель и ответы ревью подставные.

Старый код может игнорировать добавленную колонку при откате.

## Полный инфраструктурный прогон

Последний прогон выполнялся с настоящим локальным OpenSSH-сервером:

```sh
docker build -t darkfactory-smoke-ssh:local - < scripts/ssh-git.Dockerfile
docker compose exec -T -e SMOKE_SSH=1 worker python - < scripts/docker_smoke.py
```

Результат последнего прогона:

```json
{
  "result": "PASS",
  "tasks": 13,
  "bugs": 10,
  "features": 3,
  "projects": 2,
  "real_git": true,
  "git_transports": ["local", "ssh"],
  "ssh_host_key_and_identity_rejected": true,
  "real_task_containers": 11,
  "model": "deterministic HTTPS fixture, no real AI",
  "main_unchanged": true,
  "fixture_calls": {"plan": 13, "implement": 13, "review": 13},
  "repositories": "/repos/smoke-425851e2"
}
```

Все 13 задач дошли до слияния в `preprod`. Прогон использовал настоящие PostgreSQL, локальные bare Git-репозитории, временные Docker-контейнеры, команды проверок и отдельные сессии ревью. Число контейнеров — наблюдавшаяся выборка при опросе, не общее число запусков. Планирование, изменения кода и вердикты ревью возвращал детерминированный HTTPS-сервер из тестового сценария.

Первый проект работал через локальный путь, второй — через SSH. Проверены настоящий отказ при неверном ключе сервера, отказ при неверной клиентской identity и успешный доступ с правильной парой. SSH-сервер не публиковал порты хоста и удалён после прогона. Периодические проверки временного SSH-проекта отключены после приёмки; его результаты и репозиторий сохранены. Это проверка OpenSSH-транспорта, а не доступа к конкретному корпоративному серверу.

Для каждой задачи совпали принятый SHA, проверенный SHA и SHA независимого ревью. В обоих репозиториях `main` сохранила исходную вершину. Наблюдавшиеся контейнеры имели отключённую сеть, read-only root filesystem, сброшенные capabilities и не получали Docker socket либо общие каталоги `/data` и `/repos`.

## Реальный Codex и директор

`scripts/live_codex_smoke.py` проверил 10 исправлений и 3 функции на двух настоящих bare Git-репозиториях `/repos/live-codex-92f2b81c`. Планирование, код и независимое ревью выполнял настоящий Codex CLI через разрешённое персональное подключение с моделью `gpt-6.1-sol`. Платный API и детерминированная модель в этом прогоне не использовались.

Итоговый независимый тест запустил отдельный контейнер и проверил поведение double/triple на положительных и отрицательных значениях. Все 13 задач слиты в `preprod`, `main` обоих репозиториев не изменилась. Наблюдалось 37 контейнеров при опросе; это выборка, не общее число запусков.

Шесть задач остановились на лимите исправлений из-за ошибки фабрики при сохранении Git-конфликтов. Ошибка устранена и проверена на настоящем Git. Пользователь явно разрешил ещё по три цикла этим задачам; потраченное время и счётчики сохранились. Код тестовых проектов вручную не исправлялся. Финальная проверка использовала прежний checkpoint `/data/live-codex-smoke.json`, не запускала второй пилот.

Директор выполнил реальный запрос через Codex CLI: создал ровно один пул `Director CLI proof 20261021` (`dfec64be6a16448cabfc82cf6bc1a177`). Диалог `ead8d178d2b445cba98fd674e1ad6100` завершился успешно; receipt содержит `POST /api/pools` с HTTP 201. Терминальная команда `uv run darkfactory director --resume ...` получила этот же ответ через API без повторного создания пула. Затем новая команда из терминала создала диалог `aab21876055e4f49bd8b6a7f0f143995`: настоящий Codex вернул название и ID пула, не изменяя данные.

Регрессии директора проверяют ограничения API, права и область проекта, приватность истории, очередь, аренду аккаунта, восстановление без повторения неопределённых действий и удаление `user_code` из model prompt и receipts. Тесты CLI проверяют авторизацию, проектный контекст, ожидание ответа, ошибки API и продолжение ожидания без повторной отправки.

## Интерфейс

Новый раздел **«Агенты, скиллы и MCP»** открыт и проверен в браузере. Кнопка готовой команды сохранила четыре роли, шесть скиллов и два MCP через настоящий API. Каталоги и назначения используют списки; расширенные формы оставлены для своих подключений. Встроенные MCP проверены на настоящих файлах и Git: ограничения каталога, symlink, `.git`, размера, времени и опасных Git-настроек.

Правый диалог **«Директор фабрики»** проверен при ширине 1440 и 390 пикселей. На телефоне он открывается отдельной панелью; выбор контекста и поле сообщения доступны. Снимки проверки: `/tmp/darkfactory-agents-desktop.png`, `/tmp/darkfactory-chat-mobile.png`.

Через настоящий браузер проверены создание проекта и пула, создание задачи, открытие карточки, история и отмена задачи. Отменённая задача отображается в завершённых. В журнале браузера зафиксирован временный `ERR_CONNECTION_REFUSED` во время пересоздания приложения; после запуска API снова отвечает.

Дополнительно проверены API-токены `owner`, `operator` и `observer`, ограниченные одним проектом. Каждый видит только этот проект. Владелец открывает форму его настроек; оператор и наблюдатель не получают кнопку редактирования. Создание проектов и пулов организации скрыто во всех трёх случаях. Временные токены отозваны после проверки. Исправлен интерфейс: раньше настройки проекта были доступны только владельцу всей организации, хотя API разрешал владельцу проекта редактирование в своей области. Образ приложения пересобран; SHA-256 `app.js` в контейнере и рабочем каталоге совпадают.

Параллельное обновление настроек проверено в браузере с одновременной выдачей двух ответов API. До исправления три проекта давали шесть строк, после исправления — ровно три. Список пулов и проектов теперь заменяется целиком, без конкурентного дописывания строк.

Промежуточный повторный прогон остановился при заполнении диска Docker до 100%: проверка обнаружила пустой исходный файл и не допустила слияния. Освобождено 2,89 ГБ кэша сборки; тома и данные сохранены. Незавершённые задачи только этого тестового запуска отменены, мониторинг удалённого SSH-стенда отключён. После очистки новый полный прогон `/repos/smoke-425851e2` завершился 13/13; временный SSH-контейнер удалён.

- Проверка внешних PR/MR и доступа к конкретным корпоративным Git-серверам. OpenSSH проверен полным локальным Docker-прогоном; интеграции PR/MR пока проверены протокольными тестами.
